- (direction) Fast path, autonomous (Jarad 2026-11-23: 'run bmad-architecture on v1a'). Spine is the only deliverable; audience is the agents building v1a epics.
- (constraint) Inherited from PRD (final 2026-11-23): Node 24 ESM .mjs, no package.json, zero deps; policy.json is the only deploy policy; deploy targets pinned in devices.json; hermetic tests; no new clock (candybar only); Mac lock dir on the Mac's disk
- (constraint) Brownfield: lock.mjs is the one lock/queue/lease store (AGENTS.md: never add a second lock, queue or device store); several hub versions run against one lock dir at once (pins, current, hub-device release dir)
- (event) g33 ecosystem-route not installed on this host; activation prepend step skipped, ownership is the hub repo (mobile-deploy-hub) per AGENTS.md
- (version) Node 24 (mise pin 'node = 24'): local v24.6.0; current 24.x LTS 'Krypton' is v24.22.3 (nodejs.org dist index, 2026-11-10). No npm deps; only node: builtins (fs, child_process, os, crypto). Verified 2026-11-23.
- (decision) Paradigm: shared library over a file-system protocol. lock.mjs owns every mutation of HUB_LOCK_DIR (locks, queues, Reservations); the on-disk layout is the contract between concurrently running hub versions. Binds all v1a units; prevents a second store or a caller writing lock-dir files directly. Why: NFR-1 + several pins act on one dir.
- (decision) Queue scope: only the Queued set (adb, s24, mac-ios, emulator-N) joins the FIFO; withLock on those names routes through the queue path; s3-*, s3-index, emulator-reaper stay bare mkdir and emit no events. v1a holds the set as one constant in lock.mjs; v1b Registry becomes its source. Why: FR-8 last consequence; internal locks are short and high-frequency.
- (decision) Every timeout of a Queued lock throws code HUB_LOCK_TIMEOUT and its message starts with 'host lock <name> is held' (by holder, or by N waiters ahead). Why: catchup.mjs:469/591 regexes and pinned catch-ups parse the text; today's queued wording ('has N waiter(s) ahead') would read as an error. New code branches on .code only.
- (decision) Ticket format v1 frozen at v1a (NFR-2): file name <ms15>-<counter6>-<pid8>.json unchanged; body {format:1, kind: lease|job|hub-job|remote, id, holder, why, pid, host, host_id, process_start, enqueued_at, repo, run, attempt, job, reservation, eta, expires_at}. kind remote has no pid and is live until expires_at; v1 writes none. Unknown kinds are treated as live until expires_at, else live (never pruned by kind alone).
- (decision) Reservation-backed tickets are named with the Reservation's reserved_at ms, so every version that sorts by file name places the run's request at the Reservation's arrival place. No separate ordering field.
- (decision) Reservations: <name>.reservations/<repo-slug>--<run_id>.json, never an owner, never pid-bound; liveness only from timestamps (reserved_at, expires_at = reserved_at + ceiling, grace_started_at). Written by gate (adb, Linux) and preflight-ios (mac-ios, on the Mac). Same-run passthrough = same GITHUB_REPOSITORY + GITHUB_RUN_ID (reruns keep run id). Released by the last hold-taking job of that resource (android, ios) in finally, by announce as backstop (local + ssh hub-mac), else ceiling.
- (decision) Grace: stamped once (grace_started_at written into the Reservation) by the first acquiring claimant that finds the Resource free with an unasking Reservation at the head; status never writes. After grace ends the Reservation keeps its place but never blocks a free Resource again.
- (decision) A waitMs:0 attempt (phone passes in takeAnyPhone) is a try: writes no ticket, succeeds only if the lock is free and nothing live is ahead, emits an event only on acquire. The catch-up enqueues normally as kind hub-job with a short wait budget (FR-7), and only when it has a pending build to deliver.
- (decision) Peek: when the plan job finds adb held by a Lease, it reads the S26's installed version without taking the lock, through the already-running adb server only (never start-server or connect; blank RUNNER_TRACKING_ID; uses the Lease's adb_port/adb_id when recorded). No server or no device -> installed version unknown; plan proceeds and the install-time newer-device refusal (android.mjs:126) is the guard. A Job Hold of another deploy is waited for normally.
- (decision) FR-30 Android: android.mjs catches HUB_LOCK_TIMEOUT on adb and marks the delivery pending with public reason 'S26 busy' using the existing latest.json status 'pending' (enum frozen, no new keys); holder identity goes only to the receipt and the Event Log. Behaviour change logged: Play upload and the release now proceed for contention-pending builds.
- (decision) Wait deadline for deploy jobs = job start + job timeout - wait margin - per-lock hold allowance (policy). Job timeout reaches tools as HUB_JOB_TIMEOUT_MINUTES set per job in mobile-deploy.yml next to timeout-minutes; a conformance test asserts they match. Job start = start time of the nearest Runner.Worker ancestor process, else the tool process start.
- (decision) All queue tuning values live in policy.json under one strict 'queue' block (grace, reservation ceiling, wait margin, hold allowance per lock, deploy-target lease max 60, catch-up attempt, ETA window). lock.mjs reads them through loadPolicy itself; callers never pass them; tests inject a policy object.
- (decision) Event Log: <lockdir>/events/<YYYY-MM>.jsonl on the host owning the lock; one JSON line < 4 KiB per transition via O_APPEND single write; write failure logged (HUB_EVENT_LOG_FAILED) never thrown. Exactly-once: only the process whose atomic fs op (mkdir, rename, unlink, wx create) succeeded writes the event. Status and other read-only paths never write. Every event carries format:1 and hub_version.
- (decision) hub_version comes from one resolver: HUB_REF set by the action (the @vX.Y.Z the caller runs), else the release dir name in the module path, else 'unknown'. HUB_VERSION is the app version and is never used for it.
- (decision) Holders refresh owner.json mtime at most once a minute from an unref'd in-process interval while held; a reclaim records last_alive_at = owner mtime so held_ms is not inflated (FR-17). This is liveness inside one invocation, not a schedule.
- (decision) Host identity: new records add host_id (Linux /etc/machine-id, Mac IOPlatformUUID, cached per process) beside host=os.hostname(). Same-host = equal host_id when both present, else hostname equality. Fixes mDNS hostname drift on the Mac for new-vs-new; old versions see a foreign host and fall back to the conservative 4h/expiry rule.
- (decision) FR-31 v1a: every path that moves a Lease's expires_at later goes through lock.mjs extendLease, which refuses (code HUB_LEASE_EXTEND_REFUSED, names waiters+positions) while any live ticket or live Reservation waits, refuses at/after expiry, and caps deploy-target Leases (adb, mac-ios) at policy 60 min. A lease request above the cap exits 2 naming the cap and pointing at s24/emulator. The extend CLI verb and Jarad's override ship with FR-10/FR-11 in v1b/v1c.
- (decision) CLI: hub-device status text unchanged except new sections (waiters by kind, reservations) printed only when non-empty; --json gains additive keys only; status stays read-only. HUB_LOCK_WAIT becomes 'HUB_LOCK_WAIT <name> held by <holder> position=<n> eta=<range>' printed on position change or ETA move > 1 min (FR-16, the one intended text change).
- (decision) ETA: eta.mjs is pure (queue snapshot + events in, range out). IQR of matching past holds (jobs by repo+job, leases by kind x used share of stated duration), widened to stated durations/job timeouts and flagged low_data when history is thin; computed at enqueue and on position change only; the enqueue ETA is written into the ticket and the request event.
- (decision) Injected seams for all new lock-dir code: {env, now, sleep, log, host, hostId, processStart, policy, fetchImpl}. New code never calls hostname(), Date.now() or process start directly. Tests stay hermetic (NFR-5).
- (question) FR-30 for iOS: mac-ios wraps the Xcode build, export and install (ios.mjs:276), so a wait that runs out on the ios-lane leaves no artifact for the catch-up to install. v1a ships iOS contention as a red iOS job with HUB_LOCK_TIMEOUT naming holders; the preflight Reservation, the 60-min lease cap and the 120-min job timeout make it rare. Making it pending needs the build split from the ios-lane Hold, which FR-12/§7.2 defers. Deviation from PRD FR-30 for iOS -> Needs Jarad.

- (assumption) GitHub concurrency groups (cancel-in-progress false) keep one pending run per group and silently replace older pending ones; that loss is outside the hub and not counted by SM-1. Revisit if SM-1 needs it.
